## Shared shell, loading/error handling, navigation

The root wraps `QueryClientProvider`, `AuthProvider` and toaster; it supplies a 404 component and root error component with retry/home actions, and reports errors through Lovable reporting. [Root](../../src/routes/__root.tsx#L76-L128)

The authenticated shell has links to Board, BayWatch, Settings (permission-gated), and sign-out. It is sticky and `min-h-screen`, but the header nav has no mobile collapse/overflow behavior in this component; test narrow viewport layouts. [Shell](../../src/routes/_authenticated/route.tsx#L23-L68)

Primary board/bay/order/settings/message/history reads now render retryable query errors. Some secondary queries still only throw/default, notably quick-add customer/vehicle search and DVI inspection details; add equivalent error states there. ## Validation and accessibility

Check-in has hand-written field validation and accessible error associations; staff invites and server functions use Zod; the public portal validates token/decision/signature/consent schema server-side. No `react-hook-form` component use was found despite dependencies. [Check-in validator](../../src/lib/checkin-validation.ts#L1-L26) · [dialog fields](../../src/components/board/QuickAddDialog.tsx#L36-L48) · [server schemas](../../src/api/shop.functions.ts#L34-L50) · [portal schema](../../src/api/portal.functions.ts#L58-L66) · [dependencies](../../package.json#L16-L88)

## Rendering and SEO

This is not a blanket client-rendered SPA: TanStack Start is registered with `ssr: true`, but the authenticated parent sets `ssr: false`. Public login/reset/portal routes define titles and descriptions; the portal is `noindex`. The robots file allows general crawlers, and no sitemap file or public marketing route appears in the route manifest. Thus SEO is limited: the primary authenticated product is intentionally non-SSR, and `/` is an auth screen rather than a public product landing page.
